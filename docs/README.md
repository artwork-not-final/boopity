# Boopity documentation

Boopity is self-hosted software with best-effort community support. Start with
the guide for what you need to do, and use a tagged release for your installation.

## Install and use Boopity

- [Installation and configuration](guides/self-hosting.md): run with Docker or
  Node on your own host.
- [Getting started](guides/getting-started.md): complete the setup wizard and
  return to an unfinished setup.
- [Email setup](guides/email-setup.md): connect an email service for sign-in codes.
- [Operations](guides/operations.md): HTTPS, backups, updates, recovery, and
  troubleshooting.

## Develop and maintain

- [Contributing](../CONTRIBUTING.md): local development, tests, and review standards.
- [Architecture](development/architecture.md): folder ownership and dependency rules.
- [API routes](development/api-routes.md): supported endpoints and access boundaries.
- [Installer access](development/installer-access.md): setup configuration and
  recovery commands for installers and developers.

## Prepare a release

- [Release checklist](releases/releasing.md): validation and publication requirements.
- [Container review](releases/container-review.md): image findings, historical
  checks, and remaining release limits.
- [Source review](releases/source-review.md): source provenance and distribution scope.
- [Third-party notices](../THIRD-PARTY-NOTICES.md) and
  [source materials](../THIRD-PARTY-SOURCES.md): attribution and companion archives.

## Get help

See [Support](../SUPPORT.md) for community help and [Security](../SECURITY.md) for
reporting vulnerabilities privately.

Unless a guide says otherwise, run its commands from the repository root, not
from the `docs/` directory.
